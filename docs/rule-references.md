## 3. 可配置参数

通过 `--config`（TOML）可启用/禁用规则、覆盖分值/优先级、调整以下阈值。**自定义配置下维度满分按启用规则动态计算，自定义分数不代表官方评分模型。**

| 规则 | 参数 | 默认值 | 含义 |
|---|---|---|---|
| R01 | `min_chars` | 60 | README 首段最小字符数 |
| R02 | `min_hits` | 3 | 核心词最小命中次数 |
| R02 | `max_hits` | 30 | 堆砌判定阈值 |
| M02 | `max_desc_chars` | 350 | Description 最大长度 |
| M03 | `min_topics` | 6 | Topics 数量下限（最佳） |
| M03 | `max_topics` | 20 | GitHub Topics 硬上限 |
| AC01 | `new_threshold` | 90 | 新项目（<`age_cutoff`）推送窗口（天） |
| AC01 | `mature_threshold` | 180 | 成熟项目推送窗口（天） |
| AC01 | `age_cutoff` | 365 | 新/成熟项目分界（天） |

未知规则 ID、非法参数名或非法值 → 启动即报错（`ConfigError`，退出码 2），不静默忽略。

## 5. 实现与设计的已知差异

以下差异是**实现现状**，不是待办承诺；如需按 DESIGN.md 的理想规格补齐，应新建规则或调整检测函数后再更新本表。

1. **R04 不检查链接 404**：DESIGN.md §6.2 R04 的通过条件包含「链接抽查无 404」，实际实现只检查 H1 唯一、标题层级连续、代码块语言标注比例。链接存在性由 D05 覆盖，且 D05 也不做 HTTP 请求。
2. **D05 只检查链接存在性**：README 中出现任意 http(s) 链接即通过；不验证可达性、不检测死链。
3. **D02 在静态引擎中恒为 `unknown`**：`_check_d02` 固定返回 `unknown`（V1 无 Search Console/Google CSE 授权路径），不计入分母；真实收录证据只在 `repo-seo scan --verify` 的 Search Visibility Evidence 中呈现。
4. **类型标注比 DESIGN.md 更简化**：DESIGN.md 把部分规则标为「硬性+语义」，源码统一为单一 `CheckType`。例如 R03、A04 在源码中是 `hard`，A03 是 `semantic`；判定逻辑分别为正则/结构统计与关键词启发式，不等同于语义理解。
5. **语义规则的置信度为固定值**：R01 0.85、R02 0.80、R05 0.85、M03 0.85、A01 0.85、A02 0.90、A03 0.80、A05 0.85，并非按输入动态估计。
6. **文档站相关规则不做网络请求**：D03/D04 仅依据 `homepage` 与 `has_pages` 判定，不抓取 sitemap.xml / robots.txt。
7. **活跃度阈值是静态规则**：AC01 使用项目年龄分段阈值，不根据项目类型（库/应用/文档）做进一步动态校准；DESIGN.md §6.2 中「按项目类型动态评估」尚未实现。
